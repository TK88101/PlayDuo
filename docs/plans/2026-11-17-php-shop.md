### 2.2 検索（U01・U02）
- 対象は `public_flag = 1` のみ。
- `parse_search_criteria(array $get)`：対応表の name と値だけを受け付ける**ホワイトリスト**。知らない値は捨てる。価格は 0〜1,000,000 の整数のみ（それ以外は `$errors['price']` を出し、その条件は使わない）。下限 > 上限もエラー。
- キーワード：`mb_convert_kana($s, 'asKV')`（英数・空白を半角、半角カナを全角）→ 前後空白除去 → 空白で区切って**各語 AND**（「ネオン サイト」→ ネオンサイトに一致）。各語は `name` または `title_en` の部分一致。`%` `_` `\` はエスケープ（`LIKE ? ESCAPE '\\'`）。英字の大小は照合順序 `utf8mb4_general_ci` で区別しない。**50 文字（`mb_strlen`）を超えたら `$errors['keyword']` を出してキーワード条件は使わない**（切り詰めない。Codex P2）。
- SQL は条件ごとに `WHERE` 断片と値を組み立てる（列名・並び順は固定の対応表から選ぶ。入力値を SQL 文字列に入れない）。
- 並び替え：recommend＝`recommend_order ASC`、new＝`release_date DESC`、price_asc／price_desc。いずれも第 2 キー `product_id ASC`。未指定・不正値は recommend。
- U01 おすすめ：`recommend_order ASC LIMIT 4`。

### 2.3 商品詳細・カート追加（U03・U03-a）
- `product.php?id=N`：`id` は正の整数のみ。見つからない／非公開 → 404（§2.0 Q25）。
- GET：ログイン中なら `$add_block`（null／購入済み／年齢制限の理由）を用意し、HTML はボタンを disabled にして理由を出す（Q07 の決定次第）。
- 「カートに追加」POST：CSRF → 未ログインなら戻り先 `product.php?id=N` を session に置いてログインへ → `try_add_to_cart` が次の順に判定：商品が公開か → 購入済みでないか → 年齢 OK か → 通常の `INSERT INTO carts`。**重複キー（MySQL エラー番号 1062）だけ**を「すでにカートにある＝成功」として扱い、それ以外の例外は投げ直す（`INSERT IGNORE` は他の警告まで隠すので使わない。Codex P1）。
- 成功時は PRG：session に `cart_added = product_id` を置いて `product.php?id=N` へ 303 → GET で `$added = true`（1 回で消す）、`$cart_summary`（点数・小計）を用意。
- 連打：PK で 1 行。ポップアップは GET 1 回につき 1 回。

### 2.4 カート（U07・U07-a）
- ログイン必須（§2.5）。`cart_rows` は carts × products に「購入済みか」（order_details の存在）を LEFT JOIN で付けて 1 クエリ。
- `cart_view`：各行に `can_buy` と `reason`（`販売終了` ／ `購入済み` ／ `年齢制限`。優先順はこの順）。**合計と点数は can_buy の行だけ**（U07-005）。
- 削除：POST `action=delete`・`product_id`（自分の行だけ DELETE）→ cart.php に 303。
- 「購入手続きへ」は purchase_confirm.php への GET。カートが空・購入可能 0 点のときはボタンを出さず案内文（U07-a）。

### 2.5 ログイン必須と戻り先（Q05・Q06・Q26）
- 戻り先は**URL 文字列を受け取らない**。session には種類と ID だけ置く：`['page' => 'cart'|'purchase_confirm'|'product', 'id' => 正整数]`。URL は専用関数 `login_return_path(mixed $saved): ?string` が固定表から組み立てる（未知の page・不正な id は null）。保存時と使用時の両方でこの関数を通す（オープンリダイレクト防止。Codex P1）。
- `require_login(array $returnTo)`：未ログインなら上の形で `$_SESSION['login_return']` に置き → `login.php` に 303。
- login.php：
  - GET（直接開いた）で `require_login` 経由でない場合も古い値が残らないよう、**ログイン成功時に必ず取り出して消す**（単回消費）。
  - 成功時の順序：`$to = login_return_path($_SESSION['login_return'] ?? null); unset($_SESSION['login_return']); renew_session_for_auth(); … redirect($to ?? 'index.php');`（ローカル変数だけで遷移。Codex P1）。
  - `login_return` は AUTH_FLOW_KEYS に入れない（上で明示的に消費するため）。

### 2.6 購入（U08・U09・U10）— 涉钱扱い：二重送信防止・排他・原子性を明示要件にする
（「冪等」とは呼ばない。永続的な冪等キーは DB 変更になるので持たず、セッション内の確認トークンで二重送信を防ぐ。Codex P1）

**排他の規約（Codex P0 を修正採用・第2ラウンドで合意）**：購入確定と U09 の削除は、トランザクション内で
`SELECT … FROM carts JOIN products … WHERE carts.member_id = ? FOR UPDATE`（ロック読み）でカート行と商品行を読み、その結果だけで判定・書込みする。
InnoDB のロック読みは最新コミットを読み、PK (member_id, product_id) の前方一致範囲に next-key lock が掛かるので、並行するカート追加・削除・二重 POST はコミットまで待たされる。
→ members 行ロックは使わない。カートの追加・削除は単文（autocommit）のまま。

- **U08 GET**：ログイン必須 → カートが空なら cart.php → can_buy でない行が 1 つでもあれば purchase_error.php → 表示。
  確認ごとにランダムな `confirm_token`（`bin2hex(random_bytes(16))`）を作り、`$_SESSION['purchase'] = ['token', 'snapshot' => [product_id => price], 'created_at']` に置く。フォームの hidden `confirm_token` で送る（対応表に追記）。別タブで開き直すと上書き＝古いタブの確定は再確認へ。
- **U08 POST（購入を確定する）**：CSRF → ログイン必須 → token が `$_SESSION['purchase']` と一致しない・30 分超え → purchase_confirm.php へ戻す（「もう一度確認してください」）。
  ただし `$_SESSION['purchase_done'][token]` に order_id があれば**その完了画面へ**（確定済みの再送）。
  → `place_order(pdo, member_id, snapshot, now)`：
  1. トランザクション開始 → 上のロック読み
  2. `cart_view` で再判定（Q11 の 2 回目）。購入不可があれば `ng`（何も書かない）
  3. カートが空なら `empty`
  4. ロック読みの結果（商品の集合と価格）がスナップショットと一致しなければ `changed`
  5. `INSERT orders` → 各商品 `INSERT order_details`（商品名・価格は**この時点の値**）→ `DELETE carts`（購入した商品だけ）→ コミット
  6. それ以外の例外はロールバックして投げ直す（500＋ログ。UNIQUE 違反を「購入できない」に読み替えない。Codex P1）
- 結果：`ok` → `purchase_done[token] = order_id`、`purchase` を消す → `purchase_complete.php?id=<order_id>` に 303。`ng` → purchase_error.php。`empty`・`changed` → `purchase` を消して cart.php／purchase_confirm.php へ、メッセージ「カートの内容が変わりました。もう一度確認してください」（「直近の注文」には飛ばさない。Codex P1）。
- **U09**：ログイン必須 → 購入不可の行がなければ cart.php（U09-011）。`$ng_items`（name・reason）と内訳の件数。POST「対象商品を削除してカートへ」→ トランザクション内でロック読み → **その時点で**購入不可の行だけ DELETE（0 件なら何もしない）→ cart.php。「削除せずにカートに戻る」は cart.php へのリンク。
- **U10**：`purchase_complete.php?id=N`、ログイン必須、**自分の注文だけ**（他人の ID・存在しない ID は 404）。再読込しても再注文しない（GET は読むだけ）。日時は `yyyy/MM/dd HH:mm`。

### 2.7 年齢（Q16）
- `age_on(string $birthDate, int $now): int`（日本時間の今日で満年齢。2/29 生まれは平年 3/1 から加算＝PHP の日付比較で `md` を比べる方式で、2/28 時点では未到達）
- `cero_min_age`：A 0・B 12・C 15・D 17・Z 18。未知の値は **18**（安全側）。不正値が入らないよう、商品登録（A06、管理者：商品管理）で A/B/C/D/Z のホワイトリスト検証を入れる（そのタスクで実施。Codex P2）。

## 5. 受け入れ基準（スクリプトで判定）
1. `php vendor/bin/phpunit` 全緑（既存 138 件を含む）
2. `composer coverage` が 80% 以上で exit 0
