### 2.0 前提として明記する仕様（趙既裁定・Codex 指摘で明文化）
- **TOTP はパスワード再設定（U14）専用の本人確認要素**。ログイン U06 はメール＋パスワードのみ（対応表 U06 の name どおり）。ログイン MFA は今回の要件外
- ロックは**アカウント単位のみ**（IP 単位・レート制限は要件外）。第三者がメールを知っていれば 10 分ロックさせられる DoS と、ロック表示（U06-b）による会員存在の推測は**受容したリスク**として記録
- メール送信基盤なし（業務フロー方式 A）。**メール所有確認はしない**
- `totp_secret` は演習環境のため DB に Base32 平文保存（暗号化しない）
- 復旧コードの再発行・残数表示は今回範囲外（将来マイページで「現在の TOTP を要求し、既存コードを全失効して再発行」の方針）
- 全端末のセッション一括失効は要件外（DB に session 情報・世代列が無く、DDL は変えない）

### 2.2 session と CSRF
- `start_app_session()`：`session_set_cookie_params(['path'=>'/', 'httponly'=>true, 'samesite'=>'Lax', 'secure'=>HTTPS 判定])` ＋ `ini_set('session.use_strict_mode','1')`・`use_only_cookies=1`（XAMPP php.ini は use_strict_mode=0・httponly 空を実測確認済み）。`secure` は `$_SERVER['HTTPS']` があるときだけ true
- 認証系全画面（U04〜U18・U06・U14・U15）に `Cache-Control: no-store` を送る（特に U18 の復旧コードを履歴・キャッシュに残さない）
- CSRF：session ごとに `bin2hex(random_bytes(32))`。全 POST で `hash_equals` 照合、失敗は 400 で終了
- `session_regenerate_id(true)`：ログイン成功時・U14 本人確認成功時
- ログイン成功・ログアウト時は `register`・`password_reset` の途中状態を必ず破棄
- ログアウト手順：`$_SESSION = []` → session cookie を期限切れで再送 → `session_destroy()`
- flash：`$_SESSION['flash']` に入れ、次画面の `$message` で 1 回だけ出す

### 2.4 DB 操作の原子性（member_repo.php）
並行リクエストでの二重使用を防ぐため、**会員行を `SELECT … FOR UPDATE` でロックするトランザクション内**で判定と更新を行う。

| 関数 | 内容 |
|---|---|
| `create_member_with_codes($pdo, $data, $codeHashes, $now)` | members INSERT ＋ recovery_codes 10 件を 1 トランザクション |
| `find_active_member_by_email_for_update($pdo, $email)` | `withdrawal_flag = 0` の行を FOR UPDATE |
| `consume_totp_step($pdo, $memberId, $step)` | `UPDATE members SET totp_last_step = ? WHERE member_id = ? AND (totp_last_step IS NULL OR totp_last_step < ?)`、**影響行数 1 のときだけ成功** |
| `consume_recovery_code($pdo, $codeId, $now)` | `UPDATE recovery_codes SET used_at = ? WHERE recovery_code_id = ? AND used_at IS NULL`、**影響行数 1 のときだけ成功** |
| `record_failure($pdo, $member, $now)` / `reset_failures($pdo, $memberId)` | 失敗回数の加算とロック開始／成功時の 0 クリア（`$member` は同一トランザクションで FOR UPDATE 済みの行） |

**認証試行のトランザクション境界（ログイン・U14 共通）**
```
$pdo->beginTransaction();
try {
    $m = find_active_member_by_email_for_update($pdo, $email);   // 無ければ commit してダミー verify → 一般エラー
    if (is_locked($m, $now)) { commit; return LOCKED; }
    $ok = 照合（password_verify／TOTP＋consume_totp_step／復旧コード＋consume_recovery_code）;
    $ok ? reset_failures(...) : record_failure($pdo, $m, $now);
    $pdo->commit();
} catch (Throwable $e) { $pdo->rollBack(); throw $e; }
```
- 失敗回数の加算に使う値は FOR UPDATE で読んだ行の値（古い値を使わない）

### 2.5 ロック（ログイン・再設定で共通）
- 定数：`MAX_FAILURES = 5`、`LOCK_SECONDS = 600`
- 判定 `is_locked($member, $now)`：`locked_at` があり `now < locked_at + 600`
- ロック中：パスワード・コードを**照合せずに** U06-b（`$locked = true`）／U14 のロック表示
- ロック期限切れの行：失敗回数を 0 とみなして数え直す（次の失敗で 1）
- 失敗時：回数＋1、5 に達したら `locked_at = now`
- 成功時：**ログイン成功のときだけ**回数 0・`locked_at = NULL`。U14 本人確認成功・U15 再設定ではカウンタを触らない（設計書 U15 操作手順 8「再設定してもログインのロックは解除されない」に合わせ、保守的に扱う）
- 存在しないメール・退会済み：カウンタ対象外。エラー文は存在する場合と同じ「メールアドレスまたはパスワードが違います」／「メールアドレスまたはコードが違います」（列挙防止）。照合時間を揃えるためダミーの `password_verify` を 1 回行う

### 2.6 ログイン U06・ログアウト
- POST：CSRF → メール検索（FOR UPDATE）→ ロック判定 → `password_verify` → 成功なら `reset_failures`・`password_needs_rehash` なら再ハッシュして保存・途中状態破棄・`session_regenerate_id(true)`・`$_SESSION['member_id']` → `index.php` へ（U01 は今回範囲外のため遷移先は未実装。テストは Location ヘッダで判定）
- ハッシュは `password_hash($pw, PASSWORD_DEFAULT)` に固定
- ログアウト：`logout.php` は POST＋CSRF のみ受け付け、session を破棄して `login.php` へ。header.php 骨架ではログアウトを小さな form にする（対応表の「画面なし」と矛盾しない）

### 2.7 パスワード再設定 U14 → U15
- U14 POST：CSRF → メール検索（FOR UPDATE）→ ロック判定 → `code` が数字 6 桁なら TOTP（前後 1 窓・`consume_totp_step`）、それ以外は復旧コード（正規化：大文字化・ハイフン／空白除去 → 未使用コードを順に `password_verify` → 一致したら `consume_recovery_code`）
  - 失敗：共通カウンタ＋1、一般化したエラー
  - 成功：（カウンタは触らない・2.5）→ `session_regenerate_id(true)` → `$_SESSION['password_reset'] = ['member_id'=>…, 'issued_at'=>$now, 'password_fp'=>hash('sha256', 現在の password 列)]` → U15 へ
- U15：認可状態が無い／`now >= issued_at + 600`（`RESET_AUTH_SECONDS`）なら認可を消して U14 へ（flash「最初からやり直してください」）
  - POST 検証 NG：認可は残したまま再表示
  - 成功：トランザクション内で会員行を FOR UPDATE → `withdrawal_flag = 0` かつ `hash_equals(password_fp, hash('sha256', password))`（U14 以降に他所でパスワード変更・rehash・退会が無い。rehash でも安全側に失敗＝再認証を求める）を確認 → `UPDATE members SET password = ? WHERE member_id = ?` → 認可を消す → `session_regenerate_id(true)` → flash「パスワードを再設定しました」で `login.php` へ。確認に落ちたら認可を消して U14 へ
  - **`member_id` はリクエストから一切受け取らない**
  - 世代確認に `password_fp` を使うのは、DDL に `password_changed_at` 等が無く、変えない方針のため（ハッシュ値自体は session に置かず指紋のみ）

### 2.8 TOTP（hash_hmac 自作）
- RFC 6238 / RFC 4226：`hash_hmac('sha1', pack('J', $step), $key, true)` → dynamic truncation → `% 10**6`、ゼロ埋め 6 桁
- `totp_match_step($secret, $code, $now)`：`$s = intdiv($now, 30)` の `s-1, s, s+1` を `hash_equals` で比較し、一致した step を返す（無ければ null）。再利用判定は DB 側の `consume_totp_step` が担う
- Base32：RFC 4648 アルファベット、パディングなし。decode は不正文字・空文字で例外
- 自作は趙既裁定（hash_hmac 自作）。`pack('J')` は 64bit PHP 前提（XAMPP・brew とも 64bit）。テストは RFC ベクタ 5 点（59→287082、1111111109→081804、1234567890→005924、2000000000→279037、20000000000→353130。全て XAMPP PHP で実算一致済み）＋Base32 異常系＋前後窓の境界（s-2・s+2 は不一致）＋数字以外・桁違いの入力

### 2.9 入力チェック（U04・U15）— 画面設計書（利用者）v1.1 で確認済み（11/9）
出典：`チーム開発(利用者)_修正版 1.xlsx` の U04 シート入力チェック表（31〜44 行）・入力例、U15 シート操作手順。
| 項目 | 設計書 | 実装 |
|---|---|---|
| 氏名 | 必須 | 必須＋DB 列に合わせ 50 文字以内 |
| メール | 必須・形式・重複なし | `FILTER_VALIDATE_EMAIL`・255 文字以内・未登録 |
| パスワード | 必須・形式（入力例「半角英字・数字をそれぞれ含む8文字以上」） | `^[\x21-\x7E]+$`（半角のみ）・英字と数字を各 1 以上・8〜72 文字（半角限定なので文字数＝バイト数で bcrypt 上限と一致） |
